RTOS Synchronization Primitives

The theory foundation for designing multi-threaded firmware with a real-time operating system: how tasks are scheduled, how they communicate and synchronise, what goes wrong, and how to design so it doesn't.

After this course you will be able to
  • Explain how a preemptive RTOS schedules tasks, switches context and handles interrupts.
  • Choose correctly between semaphores, mutexes, event groups, task notifications and message queues.
  • Recognise and prevent deadlock using the four Coffman conditions.
  • Explain priority inversion and how priority inheritance and priority ceilings bound it.
  • Assign priorities, size stacks, protect shared state and use the kernel safely from ISRs.

How to use this course

Work through the lessons in order; each one builds on the previous. Every lesson has the same structure: learning objectives, the concept in plain language with precise definitions, a diagram or interactive animation, a worked example, common mistakes, and a "What this becomes in Zephyr" note that names the equivalent API on the STM32F769I-DISCO board. The concepts are platform-neutral; the Zephyr notes connect them to the hands-on tutorial series that follows.

Navigate with the sidebar, the links at the bottom of each page, or the ← and → keys.

Target platform for the tutorials

The concepts apply to any RTOS. The Zephyr notes and the later tutorial series use Zephyr RTOS on the STMicroelectronics STM32F769I-DISCO: an STM32F769NI microcontroller with a single Arm Cortex-M7 core at up to 216 MHz, double-precision FPU, L1 instruction and data caches, 2 MB flash and 512 KB SRAM.

Two conventions to keep in mind when moving between the theory and Zephyr:

  • In the lessons, "higher priority" means more urgent. In Zephyr, a lower number is a higher priority, and negative numbers are cooperative.
  • The lessons say task; Zephyr says thread. They are the same thing.
